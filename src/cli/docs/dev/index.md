# qtcloud-code CLI 架构

## 定位：约束驱动生成

qtcloud-code CLI 是 **AI 编码交付的约束器**——用其他 AI（pi/dsh/Claude Code 等）写代码时，约束 AI 最终交付的**代码、测试、文档三者对齐**。

```
约束（契约定义）──→ AI 生成（代码+测试+文档）──→ audit 校验
     ↑                                              │
     └────────────── 问题清单反馈 → AI 修正 ─────────┘
```

## 核心：audit（对齐审计）

AI 交付后，audit 校验三角对齐（机器可判定）：

| 边 | 校验内容 | 机制 |
|----|---------|------|
| 代码 ↔ 文档 | API 结构一致（函数/签名/参数） | 提取器（AST）↔ 文档声明对比 |
| 代码 ↔ 测试 | 测试引用的 API 存在且签名一致 | 静态分析测试引用 ↔ 代码导出 |
| 测试 ↔ 文档 | 文档声明的行为有测试覆盖 | 文档声明集合 ↔ 测试引用集合 |

输出：**问题清单**（{类型, API, 位置, 期望, 实际}）——清单即 AI 的修正任务。退出码 0/1，可入 CI（合并前 audit 必须绿）。

详见 [audit.md](audit.md)。

## 约束生效方式

1. **生成前**：契约（contract.yaml）定义代码/测试/文档的对齐要求——作为 AI 任务的规格输入
2. **生成后**：audit 校验满足度 → 问题清单反馈 → AI 修正 → 再 audit → 绿交付
3. **CI 门禁**：合并前 audit 必须绿（约束强制执行）

## 命令形态（规划）

```
qtcloud-code audit --contract contract.yaml   # 对齐审计（核心）
  --json                                      # 机器可读问题清单（AI 消费）
qtcloud-code contract init/list/validate      # 契约管理（已有）
```

## 设计原则

- **约束先行**：契约是生成任务的规格输入，不是事后检查清单
- **机器可判定**：对齐校验不依赖 LLM 判断（提取/对比/静态分析）
- **反馈可消费**：问题清单结构化——AI 直接按清单修正
- **只读安全**：audit 不修改任何文件
