## D1 example 是否内联实验室实现

背景：不侵入要求 example 不改 `src/`，但 reflect 实现当前不在 `lib.rs` 中，example 无法经公开 API 调用。

选项：

1. 每个 example 自包含，内联所需实现，仅用现有依赖；
2. 先在 `lib.rs` 暴露 `pub mod reflect` 再写薄 example，等同提前进入阶段二。

建议：选 1，符合不侵入与「先 example 后 src」的次序。

状态：2符合我的意图。

## D3 compute_confidence 是否迁入

背景：实验室的证据锚定率置信度（行号/变量名引用计数分级）生产缺失，但与 `src/llm.rs` 现有 `confidence` 字段（LLM 自评 confirm/dismiss）语义不同。

选项：

1. 迁入 `src/llm.rs`，作为对 LLM 输出的确定性置信度；
2. 迁入 `src/reflect/`，作为证据链质量指标；
3. 本轮不迁。

建议：选 2 或 3，先定「置信度」归属层再动手。

状态：先写到example里，再决定如何统一语义。

## D4 graph 输出契约

背景：现有 `run_reflect_graph` 固定打印「调用: 0, 被调用: 0」，`tests/reflect.rs` 仅断言 JSON 含 `name`。真实调用图会改变文本输出。

选项：

1. 保持既有字段与退出码，JSON 追加 `callees`/`callers`，文本填充真实数值；
2. 重排 JSON 结构。

建议：选 1，追加不破坏。

状态：2，重新设计。
